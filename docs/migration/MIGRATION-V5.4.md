# V5.4迁移与部署

## 保留原局

- 普通恢复不升级，原比赛保持原ID、修订、轮数与状态。
- 新比赛默认5.4，存档结构版本仍为5。新规则不追溯改变旧局评分或历史。
- 存档窗口提供“以V5.4创建分支”；API为 `POST /api/load {"id":"原比赛ID","round":60,"rulesRevision":"5.4"}`。分支生成新ID和lineage，保持暂停。不要把此示例请求用于自动部署。
- 已结束比赛不能迁移继续；普通查看、导出和恢复保持原结果。

## 迁移状态

5.3分支保留治理样本、项目、付款、战争、条约、福利、宗教和资产。没有历史启用记录时能力未使用，不补发资源、补助或过去责任。

既有 `extraction` 使用记录始终保留，恢复同一局或再次创建同修订分支不能重置。创建自使用前历史轮次的独立分支仍保留其真实历史状态，不伪造后来的行动。

更早版本先通过已有显式迁移链；原国教超过两个、旧军国高待遇等既有不兼容限制仍有效，不剥夺制度或改写历史。

新增状态包含原保护舰船ID、恢复轨迹初值、公开事件、通牒、补助账目、连续合格日期及监督关联，全部参与状态哈希和原子保存。

## 服务重启

活动比赛须先暂停、等待退出并保存轮边界。已干净提交的暂停边界恢复采用只读路径，不追加恢复日志或重写原文件；确有中断尝试时继续对账、审计并保存。

验证应在隔离目录和8790浏览器测试服务完成；重启后不自动创建、迁移或推进比赛。部署前后核对版本、比赛ID、轮次与状态哈希。
