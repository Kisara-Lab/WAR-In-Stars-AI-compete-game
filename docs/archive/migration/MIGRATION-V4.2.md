# 4.2分支与上线

普通「恢复最新存档」「从这里继续」保留V4原修订。原始文件、哈希、历史结果不改写。新游戏默认4.2。

显式升级：先暂停并等待当前决策退出，打开「存档 / 复盘」，点击「以4.2创建分支」；也可从所选历史轮创建。新分支有新ID、父比赛/父回合/父哈希，并保持暂停。

REST：`POST /api/load`，请求见 `examples/branch-v42.json`。不传 `rulesRevision` 不升级已有V4修订。结束局不能直接创建继续运行的4.2分支；可以选择其未结束的历史轮。失败的升级请求不替换正在观察的比赛。

迁移保留战争、条约、政策、预约、国教与灯塔进度。战争开支从迁移日起计算；旧吞并不补整合期，新吞并按4.2执行。圣地当前状态可以得分；过去任期不追补，授分从迁移后的首个完整日历任期开始。新的文明与整合状态参与状态哈希。

旧历史使用快照自身修订展示及评分；重放使用原命令，不再次调用模型。V1～V3继续通过既有V4结构转换后，只有明确选择4.2才套用新平衡。

部署不会自动升级当前比赛。检查8787状态，活动局暂停并保存轮边界；重启后对照比赛ID、轮数及状态哈希，保留原修订与暂停状态。需要新规则时由用户显式创建分支。
