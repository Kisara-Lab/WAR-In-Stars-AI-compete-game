# 版本3：审计、民生、LRS 与政策

## 建筑和全国凝聚力

价格、工期、维护均来自 `src/shared/rules.ts`。维护和凝聚力以每100日为单位。

| 建筑 | 槽位 | 矿物/基础日数 | 电力/矿物维护 | 效果与上限 |
| --- | --- | --- | --- | --- |
| 行星疗养所 `sanatorium` | 地表 | 180/300 | 8/2 | 行星贡献+2，每行星1座 |
| 行星度假区 `resort` | 地表 | 260/400 | 14/3 | 行星贡献+4，每行星2座 |
| 长程传感阵列 `lrs` | 轨道 | 320/400 | 18/4 | 本地至两跳军事视野，每星系1座 |

仍有8个地表槽、6个轨道槽。数量限制包含所有施工预留。LRS必须位于己方殖民地轨道。取消返还50%，拆除返还25%，占领保留完工设施。AI自由决定建筑比例，不存在强制行星职业。

每颗行星前两座矿场无惩罚，此后每座−2。四矿−4，六矿−8，八矿−12。全国建筑贡献为所有己方殖民地的「正民生贡献×供应倍率−矿业惩罚×政策惩罚倍率」按人口占比加权。

全部供应正常时基础+1；任何短缺取消基础收益。食物、电力、矿物维护短缺分别−12、−4、−4，允许叠加。每种短缺使供应倍率×0.5，正民生和正政策凝聚力收益受此修正，负惩罚不减轻。初始两矿不会新增惩罚。

凝聚力仍为全国0～100，生产与建设倍率为`0.5 + 凝聚力/100`。每10日按比例累计，凝聚力以百分之一单位保存；本步形成的短缺从下一步生效。界面显示下一步估计，审计保存每一步实际输入与结果。

## 政策任期

政策数值集中于 `src/shared/civil.ts` 的 `POLICIES`。

| 政策ID | 名称 | 电力 | 矿物 | 食物 | 凝聚力/100日 | 战力 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| none | 不采用政策 | 1 | 1 | 1 | 0 | 1 |
| militarism | 穷兵黩武 | 1.25 | 1.35 | 0.65 | −4 | 1.10 |
| utopia | 乌托邦 | 0.75 | 0.75 | 1 | +8 | 1 |
| balanced | 均衡发展 | 0.95 | 0.95 | 1.10 | +2 | 1 |

- 所有势力使用比赛日期的统一720日任期，包括跳过。每届一次选择，不可取消、替换、叠加或自动续期。
- 第0日选择首届；未提交则锁定无政策。第700日可提前选择第720日开始的第二届，原政策持续至720日。
- 第710→720日的模拟步使用原政策，第720→730日使用新政策。未预选的下一届自动无政策。换届发生在每10日步末，日志区分明确选择和未提交默认跳过。
- 资源倍率作用于生产总量，维护不变。穷兵黩武额外将矿业与短缺凝聚力惩罚×1.5。政策不直接改变固定探索/殖民工期或建筑基础工期。
- 战力倍率同时作用舰船和基地；胜方船体伤害为「败方有效战力×0.5÷胜方完整供应/政策战力倍率」。

工具示例（可放入 `submit_turn.orders`）：

```json
{"type":"choose_policy","args":{"policy":"balanced"}}
```

## LRS 与当时所知

军事视野和行星经济情报分别保存。LRS覆盖建设星系及沿航道1、2跳的星系，不延伸到第三跳，不自动探索。多个阵列取并集。

军情包含舰队ID、归属、数量、船型、每艘船体、坐标，以及基地归属和船体。没有敌方命令、生产队列、资源、内部政策、人口或行星设施。原有探索/本地情报可以保留，但单独标明日期，LRS不能刷新经济情报。

只有航道两端均被LRS覆盖时才能持续追踪在途舰队。离境保留方向与最后日期，区外进入时到达覆盖星系后重新发现。断电或矿物维护短缺停止运转；食物短缺不缩短范围。拆除、失去主权后撤销覆盖，历史情报保留。发现未知势力军事单位可触发双边首次接触。

观察者仍拥有全图事实。选择观察势力会显示蓝色LRS圈，以及本地/LRS/最后已知来源；这不会把观察者信息传给AI。

## 每局档案

默认目录 `.data/matches/<比赛ID>/`：

| 文件 | 内容 |
| --- | --- |
| initial.json | 开局状态与哈希、规则版本、父分支信息 |
| audit.jsonl | 追加审计日志，完整公开过程，无1500条上限 |
| round-0001.json 等 | 原子提交的逐轮状态、决策、状态哈希、attemptId和auditHash |
| checkpoint.json | 最新检查点，可从原子回合文件重建 |
| meta.json | 存档目录索引 |
| chronicle.md | 确定性中文编年史，结束时自动生成，也可手动导出 |

浏览器、`simulate`和`smoke:ai`使用同一个记录器。纯模拟单元测试和`benchmark`不创建正式比赛日志。

JSONL每条包含`seq/time/day/round/category/attemptId/factionId/systemId/data/previousHash/hash`，可选字段按实际关联出现。SHA-256覆盖除hash外的整条JSON对象，链连接上一条hash；状态另有独立哈希。它用于检测文件损坏和不一致，不是第三方签名证明。

主要类别：

| 类别 | 用途 |
| --- | --- |
| match.initial / match.branch | 初始完整规则、状态、种子、模型和历史来源 |
| attempt.started / attempt.aborted | 同一轮的不同决策尝试；中断保留但不提交 |
| model.request / response / failure / retry | 实际过滤后情报、提示词、工具定义、请求参数、公开输出、HTTP结果与用量 |
| model.tool / decision.completed | 原始参数、校验结果、预留资源/项目、公开战略与接受命令 |
| event.* | 完整游戏事件，命令执行/冲突、政策、外交、战斗和主权变化 |
| movement.step | 每10日位置及在途变化，包括航道进出 |
| economy.step | 每10日生产、维护、库存前后、供应/政策倍率和凝聚力分解 |
| round.prepared / committed / recovered | 提交状态哈希、回合与日志关联及重启对账 |
| runtime.* | 开始、暂停、保存、恢复、错误和结束 |

战斗事件保存逐对结算顺序、参战单位与船体、修正倍率、有效战力、幸存船体；主权事件保存前后基地归属。通过舰船ID对照前后可还原损失。

模型请求/返回及时刷盘，每步事件批次统一刷盘。所有输入、公开输出、错误及工具参数统一脱敏。认证头和密钥不进入记录；隐藏推理和加密推理项不持久化。为保持接口协议，本轮内存会话可暂存模型返回的协议项。

## 提交、暂停与恢复

1. 创建新的尝试ID，记录双方/多方实际获得的情报，各方并发规划。
2. 任一方失败则取消其余请求，公共世界保持原轮边界。已收到的公开输出仍可审计。
3. 模拟在副本上运行，逐步追加候选事件和经济记录。
4. 写入`round.prepared`，然后原子替换回合文件。**回合文件存在且哈希通过才代表提交**，单独的模型意图或模拟日志不能证明已经发生。
5. 写入提交标记和检查点。提交后缓存写入失败不会回退世界或重复执行该轮，比赛暂停显示原因。

服务重启从独立会话指针恢复；校验原始状态哈希、日志序号/哈希链以及回合的审计引用。未提交尝试标记为中断，已提交轮次不重跑。恢复后保持暂停，不自动调用模型。尾部不完整或哈希损坏会明确报错，保留原日志供检查，不静默删除内容。

历史查询不修改快照。恢复版本1/2时创建版本3新分支，记录父比赛、轮次和原哈希，保留原地图和外交；本届无政策，下届开放选择。旧版历史仅导出实际保留资料，明确缺失原始请求和被截断事件。

## 查询与导出

- `GET /api/matches/:id/audit?after=0&limit=40`：分页，每页最多200条。过滤`factionId/systemId/category/attemptId/fromDay/toDay`；category支持前缀，例如`event.battle`或`model`。返回派生的`committed`标记及`next`游标。
- `GET /api/matches/:id/export/jsonl`：导出原始哈希链日志；旧档导出现存快照并标明覆盖缺口。
- `GET /api/matches/:id/export/markdown`：按年份、轮次组织已提交事实，引用公开战略对应审计序号；失败/未提交意图单独列出，不写作战果。

编年史无需再次请求模型。同一日志内容下顺序及文本保持稳定。审计页可按尝试查看完整决策详情，并直接下载两种格式。查阅当前比赛时，尚未完成的记录标为「未提交／进行中」。审计JSONL是原始过程；判断崩溃边界的最终事实需结合原子回合文件，或使用已完成对账的查询/编年史。

配置请求示例仍见 `examples/match.json`，政策由AI按任期自主选择，不由创建比赛参数强制指定。可在 `examples/policy-turn.json` 查看政策与新设施工具参数。环境示例只含占位值；正式环境文件始终由后端读取。
