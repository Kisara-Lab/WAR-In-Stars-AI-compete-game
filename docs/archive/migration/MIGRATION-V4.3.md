# V4.3 迁移与运行

普通恢复保留原规则。仅显式提交 `POST /api/load`，例如 `{ "id":"旧比赛ID", "round":58, "rulesRevision":"4.3" }`，才创建4.3分支。浏览器存档页提供对应按钮。

原文件、原哈希、旧回放和旧结果不改。创建分支会先由存储层验证原哈希，再生成新ID与父局/回合/哈希关联。分支保持暂停；已结束比赛拒绝规则迁移。

- 保留领土、战争、政策、宗教、灯塔及已有设施。
- 合金从0开始，不补发冶炼厂、人口或资源；新增开局配置仅用于新游戏。
- 原项目保持原成本和退款基数，旧舰船订单继续完工；新订单按4.3材料收费。
- 旧建筑项目按创建日期、ID进入地表/轨道各自的串行队列。
- 现有建筑按新岗位规则运营；迁移事件提供各方岗位缺口及政策收支预览。
- 不重绘地图，按原种子和原星系位置索引生成禀赋；已有探索记忆补充新规则禀赋，不改写旧存档。
- 岗位、合金、施工队列、封存/重启及扩槽均参与状态哈希。

资源类型的`alloys`字段在旧快照中允许缺失。4.3计算将缺失值视为0；不得给旧快照写入零字段后再声称原哈希未变。

## 启动与验证

```powershell
npm.cmd run build
npm.cmd start
npm.cmd test
npm.cmd run test:e2e
npm.cmd run simulate -- --factions 4 --rounds 12 --workers 2
```

服务默认127.0.0.1:8787；测试浏览器独立8790。公开测试包含旧4.3的岗位、产业、评分与视角覆盖。通用simulate工具运行当前默认修订的脚本局，不调用模型；历史一次性生产验证工具不随仓库发布。

上线保留当前比赛与修订，先确认暂停且没有进行中的决策，保存轮边界再重启；核对比赛ID、轮数、状态哈希一致。上线后仍暂停，不自动迁移或新建生产局。
