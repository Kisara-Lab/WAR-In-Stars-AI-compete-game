# V5.2迁移与部署

## 原档保全

结构版本5，规则修订5.2。普通恢复创建保留原修订的分支；只有明确选择「以V5.2创建分支」或 `/api/load` 请求 `rulesRevision: "5.2"` 才迁移。读取前继续校验原存档哈希，原文件、原结果和历史展示不改写，不允许降级。

5.2发布时新局默认5.2。超过两个国教的旧比赛不兼容，应保留原修订，不剥夺既有制度。

## 显式分支条件

- 已结束比赛拒绝迁移继续运行。
- 历史已立教国家（含淘汰者）超过两个，拒绝迁移，不剥夺制度。
- 不超过两个，保留其主圣地并永久登记名额，按新候选规则补足两颗；不能保留与补足时拒绝。
- 旧军国采用第一/二档福利时拒绝，要求先在原规则中明确改选合法待遇；不静默降档。
- 保留资产、人口、就业、项目、战争、条约、附属圣地及既得成果；不补收过去福利，不补造责任或成果。
- 新责任从分支创建日起给完整整备期。候选已被探索时只追加当前日期的“新规则勘察”事件。
- 新责任、登记、托管、报告、协议及失败反馈进入状态哈希、原子保存与恢复。

## 部署顺序

1. 检查8787比赛ID、轮次、状态哈希及活动状态。
2. 若正在推进，暂停并等待该轮退出，保存完整轮边界。
3. 类型、构建、回归通过后重启服务。
4. 检查同一ID、轮次、哈希及暂停状态，确认没有新增比赛或迁移。

部署前后应独立保存所用原局的文件指纹，验证没有改写原文件。
